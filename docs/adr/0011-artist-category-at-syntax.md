# 0011. 画师作为独立类别，输出 @画师名

- 状态：已接受
- 日期：2026-11-10

## 背景

编辑区需要把「画师」和普通提示词区分开：anima 模型用 `@kantoku` 这种语法引用画师，写进普通分区拼出来的是错的。同时画师也常需要单独调权重，不能和人物 / 场景词混在一堆分区里。

## 决策

1. 画师是词条的一个普通分类（`category = artist`），继续复用全局词库的增删改查、搜索、收藏，不新开一张表。
2. 编辑区渲染时把画师从普通分区剥离，单独收集成 `artists` 列表，统一追加在正向文本尾部，输出 `@画师名`；权重不为 1 时输出 `(@画师名:1.5)`。
3. 前端在负向卡片上方放一个独立的「画师」卡片展示结果，`+ 选择画师` 复用标签弹窗并锁定分类。
4. 存储的 prompt 不带 `@`，只在输出时拼一次，避免出现 `@@kantoku`。
5. 老库通过 `SchemaUpgrade` 把 `artist` 补进现有的 `tag.categories` JSON，并用 marker 保证只补一次。

## 后果

- 分类体系保持单一来源（设置页的 `tag.categories`），画师和普通分类共用一套自定义 / 排序能力。
- 画师不占普通分区计数，`positiveCount` 与 `artistCount` 分开统计，语义清晰。
- 画师去重按小写名合并：预设 / 词组带来的画师如果用户又在编辑区选了一次，会升级成可移除的「编辑区」来源，权重也以编辑区为准。
- 画师只能通过画师卡片进入编辑区，`normalizeSection` 会拒绝把条目手动指定到 `artist` 分区。

## 备选方案

- **单独建 `artist` 表**：字段与词条几乎一致，会多一套 CRUD 与搜索，放弃。
- **复用 `negative` 那种特殊 polarity**：极性表达的是正负向，不表达「画师」语义，混用后分区与去重逻辑都会变复杂，放弃。
- **存储时就带 `@`**：编辑区、词组、预设三处来源都要各自处理前缀，容易出现 `@@`，最终选择存储纯净、输出补前缀。
