# 0010. 编辑区存档采用独立快照表，而非「多建几个编辑区」

- 状态：已接受
- 日期：2026-11-05

## 背景

用户需要保存编辑区的多个版本。最省事的实现是「把当前编辑区复制成新编辑区」，但存档一多，编辑区下拉框会爆炸，而且存档和正在编辑的工作区混在一起，语义混乱。用户明确提出要「保存 / 读取」并支持导入导出。

## 决策

新增 `workspace_archive` 表，与 `workspace` 列表完全分离：

- 内容是 JSON 快照：workspace 配置（LoRA / 预设 / 备注）+ 条目引用（itemType / refId / polarity / weight / sectionOverride / sortOrder）+ 当时展开的正负向文本。
- 独立弹窗管理，支持备注、导入 JSON、导出 JSON、删除，数量不受下拉框限制。
- 「读取」是覆盖式恢复到当前编辑区；失效引用（词条 / LoRA / 预设被删、跨 LoRA 词组）自动跳过并在结果里计数。

## 后果

- 存档与词库后续改动解耦：快照同时存了引用 ID 和展开文本——引用 ID 用于恢复联动，展开文本用于脱离数据库查看。
- 词条被删除后读取会跳过该条目（计数提示），不会产生脏引用。
- 读取是覆盖当前编辑区而非新建，恢复前需要用户确认。
- 一张新表，直接写进 `schema.sql` 幂等建表，无需 `SchemaUpgrade`。

## 备选方案

- **存档即 workspace 行（加 archived 标记）**：下拉框仍要过滤、语义混杂，放弃。
- **快照只存展开后的纯文本条目（无引用）**：恢复后失去与词库 / 词组的联动（来源改动不再同步），放弃；最终选择「引用 + 文本快照」双写。
