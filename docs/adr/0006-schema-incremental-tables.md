# 0006. Schema 允许幂等增量演进

- 状态：已接受
- 日期：2026-11-04

## 背景

ADR-0002 在阶段 0 一次性建全 10 张表，之后约定「原则上不改表结构」。阶段 2.5c 要给词条加收藏，如果不加表，只能给 `tag` 表加 `favorite` 列——而 SQLite 加列对已有数据虽然可行，但会让「词条本体」与「用户偏好状态」混在一张表里。

## 决策

收藏用独立表 `tag_favorite(tag_id PRIMARY KEY, created_at)`，通过 `CREATE TABLE IF NOT EXISTS` 追加进 `schema.sql`；旧的「不改表结构」约定放宽为「**不修改已有表的列，但允许幂等新增表**」。

## 后果

- 好处：`tag` 表保持稳定；收藏状态可以整表清空而不影响词条；删除词条时由业务层联动清理收藏，逻辑简单。
- 约束：新增表必须沿用 `CREATE TABLE IF NOT EXISTS` 写法，保证老库启动时自动补建、重复执行无副作用；不再回头改已有列，需要列级变化时重新评估。

## 备选方案

- 给 `tag` 加 `favorite` 列：改动小，但混淆本体与偏好，且与阶段 0 约定冲突更大，放弃。
- 完整迁移工具（Flyway 等）：对单人本地项目过重，放弃；若未来列级变更增多再考虑。
