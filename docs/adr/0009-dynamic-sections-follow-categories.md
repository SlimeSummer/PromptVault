# 0009. 编辑区分区跟随词条分类，不写死「九分区」

- 状态：已接受
- 日期：2026-11-05

## 背景

README 最初把编辑区定义为「九分区组装台」（触发词 / 质量 / 风格 / 穿搭 / 场景 / 动作 / 表情 / 细节 / 负面），但自阶段 2.5a（ADR-0005）起，词条分类可以在设置页自定义新增、删除、改名、排序。两者直接冲突：分区写死的话，用户新增的分类无处显示，删除的分类留下空壳。

## 决策

编辑区正向分区不写死，渲染时实时读取 `setting.tag.categories`（排除 `negative`），分类顺序即分区顺序；负向不按分类分区，独立成一层按 polarity 合并。词条分类未知或分类被删除时回退 `other`（无 `other` 回退第一个分类）。导出文本按分区顺序 + 分区内 `sort_order` 拼接。

## 后果

- 一致性自然成立：设置页调整分类顺序，编辑区大类顺序随之变化，用户不需要额外的「全局排序」功能。
- 分区是渲染层概念，不落库；词条只存 `section_override` 覆盖值；分类被删除后相关词条自动漂移到 `other`，不产生脏数据。
- `negative` 分类永远不会成为正向分区。

## 备选方案

- **固定九分区 + 自定义分类映射进九宫格**：映射本身又是一份配置，且「自定义分类」名存实亡，放弃。
- **全局平铺排序 + 分区仅作视觉分组**：更贴近 ComfyUI 对顺序的敏感，但用户确认「调整分类顺序即可」，放弃（见 stage-4 遗留）。
