# 0004. 负向词分三层存储，导出时合并

- 状态：已接受
- 日期：2026-11-03

## 背景

负向词有三个天然来源，作用范围不同：

1. **全局通用负面**：所有图都该带上的低质量词；
2. **预设负向**：某个 LoRA/角色特有的问题（如特定崩坏特征）；
3. **词组负向**：某套经验组合自带的排除项。

如果强行合并成一张表，会丢掉"这条负向词属于谁"的语义，后续也没法单独维护。

## 决策

三层各自保存在各自的主体中：

- 全局通用负面：`tag_group` 且 `kind = 'global_negative'`；
- 预设负向：`preset_item.polarity = 'neg'`；
- 词组负向：`tag_group_item.polarity = 'neg'`。

在编辑区导出时，按「全局 → 预设 → 词组」的顺序展开并合并去重。

## 后果

- 数据层保持语义清晰，每个负向词都能追溯到来源。
- 导出/复制逻辑必须实现合并与去重；重复项的权重取舍规则在阶段 4 实现时定稿。
- 用户可以在三个层级分别维护，不必每次从头拼负向词。

## 备选方案

- **统一一张负向词表**：导出简单，但失去归属，无法按 LoRA/词组单独管理。
- **导出时只取预设负向**：实现最省事，但会丢掉全局与词组里的经验。
