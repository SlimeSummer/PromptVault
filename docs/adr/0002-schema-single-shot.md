# 0002. 数据表在阶段 0 一次建全

- 状态：已接受
- 日期：2026-11-03

## 背景

项目按阶段开发（词库 → LoRA/预设 → 词组 → 编辑区 → 导入 → AI）。
SQLite 没有成熟的迁移框架，如果每个阶段都改表，已有的本地数据库很容易不兼容。
同时，各模块之间的关系（标签、预设、词组、编辑区）需要在动手前就想清楚。

## 决策

在阶段 0 一次性建全 10 张表，后续阶段**只使用、不改结构**：

`lora`、`tag`、`preset`、`preset_item`、`tag_group`、`tag_group_item`、
`workspace`、`workspace_item`、`setting`、`import_log`。

建表脚本使用 `CREATE TABLE IF NOT EXISTS`，可重复执行。

## 后果

- 阶段 0 就要预判字段，前期设计成本高，但后续每阶段都省掉迁移。
- 部分表（`tag_group`、`workspace`、`import_log`）会空转一段时间。
- 如果确实需要改表，只能手工迁移本地库；因此字段命名尽量中性、留有余量。
- 索引随表一起建好，避免后期补索引时再动结构。

## 备选方案

- **引入 Flyway / Liquibase**：更工程化，但 SQLite 支持有限，个人项目收益不足。
- **每阶段 `ALTER TABLE`**：灵活，但旧库升级路径会越积越复杂。
