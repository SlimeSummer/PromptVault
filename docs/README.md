# 开发记录

本目录保存 PromptVault 的「生长过程」，和 README 分工明确：

- **README**：项目现在是什么样（对外展示的当前状态）
- **docs/devlog/**：每个阶段怎么长出来的（目标、改动、理由、踩坑、验证）
- **docs/adr/**：重大决策为什么这么定（一次决策一个文件，长期有效）

## 何时写

| 时机 | 写什么 |
| --- | --- |
| 每个阶段完成、验收通过后 | 新增 `devlog/stage-N.md`，并更新 README 的进度表 |
| 出现"以后可能被推翻"的技术/产品选择 | 新增 `adr/NNNN-短标题.md`，编号递增 |
| 已有决策被推翻 | 不删旧 ADR，新写一篇并把旧的标记为「已废弃」 |

## 写作原则

1. **只写事实与理由**，不写教程式讲解；一页能读完。
2. **写"为什么"比写"做了什么"更重要**——做了什么，git 里都有。
3. **记录踩坑和验证证据**，避免下次重复交学费。
4. **不复制 README**：README 是快照，devlog 是历史。
5. 阶段日志允许简短；宁可少写，也不要写完就没人维护。

## devlog 模板

```markdown
# 阶段 N：标题

> 完成日期：YYYY-MM-DD

## 目标
这一阶段要解决什么问题（1–3 条）。

## 实现内容
- 后端：新增/修改了哪些接口、服务、表（用文件路径指路）
- 前端：新增/修改了哪些页面与交互

## 关键决策
只列本阶段做的决定，并链接到对应 ADR（如果有）。

## 踩坑 / 注意
实际遇到的问题、绕过的方案、留下的隐患。

## 验证证据
编译、接口、浏览器实测结果；测试数据是否清理；端口是否释放。

## 遗留
本阶段没做、但已知要做的事（指向下一阶段或后续阶段）。
```

## ADR 模板

```markdown
# NNNN. 决策标题

- 状态：已接受 / 已废弃
- 日期：YYYY-MM-DD

## 背景
是什么问题逼着我们必须做选择。

## 决策
一句话说清选了什么。

## 后果
带来哪些好处、哪些约束或成本。

## 备选方案
考虑过但没有选的方案，以及没选的原因。
```
